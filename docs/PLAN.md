# RTL-TCP-Cast 開発計画

## 目的

コマンド操作を知らない利用者が、RTL TCPの受信データを複数アプリへ簡単に配信できるWindows GUIを提供する。

## 初版仕様

- Windows x64 / .NET 10 / WPF、日本語画面
- タブごとにローカルrtl_tcp起動（既定）または既存rtl_tcpへの上流1接続、各配信で最大16クライアント
- 12バイトのRTL0ヘッダーを検証して各接続へ転送
- IQデータは変更せず配信し、新規接続もI/Qペア境界から開始
- 5バイトのチューナーコマンドを全クライアントから転送、または集中管理で遮断
- 中心周波数・PPM・Gain・サンプルレートを集中管理。再接続時に再適用
- コマンド書き込みを直列化。UIには要求値のみ表示
- 接続失敗・上流切断を自動再試行。切断時に下流を閉じ、ヘッダーや要求値をリセット
- クライアントごとに最大64ブロックの送信キュー（1ブロック最大32KiB）と5秒の送信タイムアウト
- 接続先・配信先・自動再接続を保存し、配信の開始・停止、状態、通信量、ログ、個別切断を提供
- 配信開始中は設定編集を無効化
- 設定は変更後にsettings.iniへ自動保存し、旧JSONから移行。無効な入力は保存しない

## 検証

模擬rtl_tcpを使った通信テストで、ヘッダー・コマンドの分割受信、複数配信、I/Q境界、操作権限、再接続、不正ヘッダー、送信が遅いクライアント、ポート競合、接続上限、停止と再開始を確認する。

WPFのGUIテストで、開始・停止、設定編集のロック、一覧表示、操作モードの切り替え、個別切断、LAN設定、終了処理を確認する。描画画像も生成して目視確認する。

実際のドングル・rtl_tcp・受信ソフトを使った互換性と長時間稼働は、実機が利用できる環境で追加検証する。

## 実装済み: rtl_tcpの起動・停止

入力元を「このPCのrtl_tcpを起動する」「起動済みのrtl_tcpに接続する」から選択する。実行ファイルのパスと入力元を保存する。

Coreのネットワーク中継を維持し、別のプロセス管理コンポーネントが次を担当する。

1. 実行ファイルを参照ダイアログから選択
2. 上流ローカルポートを自動選択し、引数を組み立ててウィンドウなしで起動
3. 実際の中継接続で起動成功を確認（最大15秒）、異常終了を検出
4. 標準出力とエラー出力をログに表示
5. 「配信開始」でrtl_tcp起動→接続→配信を一括実行
6. 「配信停止」とウィンドウ終了で、アプリが起動したrtl_tcpだけを終了

既存のrtl_tcpプロセスを勝手に終了しない。実行ファイルの同梱・配布方法とライセンス対応は、この段階で決定する。

## その後の候補

デバイスと受信設定のGUI選択、トレイ常駐、プリセット、起動時の自動配信、複数ドングル、診断支援。復調、音声再生、ウォーターフォール、録音は別途必要性を判断する。

## 複数ドングル対応

- 共通設定画面でRTL-TCPパスを1つ指定
- タブごとにSessionViewと独立したRelayServer・RtlTcpProcessを保持
- デバイス番号／シリアルを-dで指定。タブ追加・削除・名前変更、一括開始・停止
- 共通設定と各セッションを1つのINIに保存。旧設定を最初のタブへ移行
- 模擬プロセス2台で同時配信、独立停止・異常終了、終了時の全プロセス停止を検証
