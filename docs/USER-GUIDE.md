# RTL-TCP-Cast 利用ガイド

## 始める前に

ZIPをすべて展開し、フォルダー内の `RTL-TCP-Cast.exe` を起動してください。インストーラーと.NETの事前インストールは不要です。RTL-TCP-CAST本体は単一の実行ファイルです。

rtl_tcp.exe、rtlsdr.dll／librtlsdr.dllと関連DLL、USBドライバーは別途導入してください。これらはRTL-TCP-CastのZIPには含まれません。

受信元は「このPCのrtl_tcpを起動する」（既定）と「起動済みのrtl_tcpに接続する」から選択できます。

## 設定ファイルのインポート／エクスポート

「ファイル」メニューから、RTL-TCP-Castの設定をINIファイルにエクスポートしたり、別のPCやバックアップからインポートしたりできます。配信タブごとの設定とアプリ全体の設定をまとめて扱います。インポートすると現在の設定を置き換え、配信中のタブを停止します。内容を確認してから確定してください。

## このPCのrtl_tcpを起動して配信する

1. RTL-SDRのUSBドングルを接続します。WinUSBドライバーを導入済みである必要があります。
2. 「設定 → アプリ全体の設定」でrtl_tcp.exeのパスを指定します。すべてのタブで共通です。
3. タブ内で「このPCのrtl_tcpを起動」を選び、「ドングル」にデバイス番号（0から）またはシリアル番号を入力します。
4. 「配信開始」を押します。アプリがrtl_tcpをコンソールウィンドウなしで起動し、自動接続します。
5. 「配信中」になったら、受信アプリへ配信PCのIPと配信ポートを設定します。

rtl_tcp.exeと一緒に配布されたDLLは、実行ファイルと同じフォルダーに置いてください。フォルダー名に空白があっても利用できます。

同じUSBドングルを使うrtl_tcpや受信ソフトがすでに起動している場合は、先に停止してください。既存のrtl_tcpをそのまま使う場合は「起動済みのrtl_tcpに接続する」を選びます。

上流のローカルポートはアプリが自動で選択します。利用者が通常画面の「配信ポート」で指定するポート（初期値11234）とは別です。起動を15秒以内に確認できない場合は停止し、対処方法を表示します。

「配信停止」またはウィンドウ終了で、アプリが起動したrtl_tcpだけを終了します。起動済みの別プロセスには影響しません。rtl_tcpが異常終了した場合、配信を停止して画面とログに理由を表示します。

## 複数ドングルと共通設定

「＋ 配信を追加」でタブを追加します。各タブは別のrtl_tcp・配信ポート・RTL-SDR設定・接続一覧・ログを持ちます。「名前変更」「削除」でタブを管理できます。削除時はそのタブが起動したrtl_tcpを停止します。最後の1タブは削除できません。

「すべて開始」「すべて停止」で一括操作できます。他タブで選択済みのRTL-SDRは一覧に表示されますが選択できません。番号とシリアル番号の両方をデバイス一覧から識別できる場合は同じドングルを判定します。一覧を取得できない場合は各タブで同じ指定方式を使用してください。配信ポートは停止中のタブも含めて重複を確認し、配信開始時に重複があればエラーを表示します。USBデバイスの抜き差しはWindowsから通知を受けて一覧を自動更新します。「更新」から手動で再取得することもできます。一覧取得にはRTL-TCPと同じフォルダーの64bit版rtlsdr.dllまたはlibrtlsdr.dllと依存DLLが必要です。取得できない場合は番号・シリアル番号を手入力できます。シリアル番号が一意のデバイスはシリアルで保存します。

共通パスは「設定 → アプリ全体の設定」の1画面で変更します。変更は次回起動から反映され、起動済みプロセスは維持します。タブの設定と名前・順序・選択中のタブはINIに保存します。従来の設定は最初のタブへ移行し、旧INIをsettings.legacy.iniとして残します。

1つのrtl_tcpが異常終了しても、他のタブの配信は続きます。アプリ終了時は全タブが起動したプロセスを停止します。

## 同じPCのアプリへ配信する

1. RTL-TCP-Castを起動します。
2. 「起動済みのrtl_tcpに接続する」を選び、接続先を入力します。同じPCなら `127.0.0.1`、通常のrtl_tcpポートは `1234` です。
4. 「配信開始」を押します。
4. 「配信中」と表示されたら、受信アプリの入力をRTL TCPに設定します。
5. 受信アプリへ接続先を指定します。同じPCならホスト `127.0.0.1`、配信ポートの初期値は `11234` です。

rtl_tcpの接続先と、受信アプリが接続する配信先は別です。受信アプリはRTL-TCP-Castの配信先に接続してください。

## LAN内の別のPCへ配信する

配信開始前に「LANへ配信」を選択してください。

受信アプリには配信PCのLANアドレスと配信ポートを指定してください。同じPCのアプリは `127.0.0.1` も利用できます。

Windowsのファイアウォールで通信の許可を求められた場合、利用するプライベートネットワークに合わせて設定してください。RTL TCPは認証・暗号化を備えていないため、信頼できるLANで利用します。

## 周波数やサンプルレートを変更する

「受信元・配信設定」の下の「SDRデバイス設定」で、中心周波数・PPM・Tuner Gain・RTL AGC・サンプルレートごとにクライアント操作ロックを選べます。チェックした項目のクライアント設定コマンドだけを遮断し、このアプリの値を編集してrtl_tcpへ送ります。チェックしていない項目は受信アプリから変更でき、アプリ側の入力欄は無効になります。配信中にロックを有効にすると、直前に受信したクライアントの要求値をアプリの値に引き継いでから固定します。要求値をまだ受け取っていない項目は、画面に設定した値を使います。

ロックは配信中も変更でき、ロックした項目は接続・再接続時にもアプリの値を送り直します。配信中にロックを有効にすると、直前に受信したクライアントの要求値を引き継ぎます。中心周波数は上下ボタン・ホイール・上下キーで6.25 kHzずつ変更でき、テキストボックスに任意の値も入力できます。PPMとTuner Gainは上下ボタン・ホイール・上下キーで1ずつ変更できます（Tuner Gainは1 dB）。Tuner Gainは手入力で0.1 dB単位も指定できます。「自動（Tuner AGC）」はRTL-SDRチューナーの自動ゲインです。RTL AGCは右端のクライアント操作ロックを有効にすると、このアプリのチェックボックスで設定でき、受信アプリからの変更を遮断します。ロックしていない場合は受信アプリがRTL AGCを変更でき、アプリのチェックボックスにも要求値が反映されます。

全アプリが同じIQデータを受信します。受信アプリの中心周波数とサンプルレートを配信設定に合わせてください。

ステータスバーの中心周波数・サンプルレート・PPM・Tuner Gain・RTL AGCは、上流へ送信した要求値です。受信機の実際の設定や、コマンドが適用された結果は取得できません。未取得の項目は「—」を表示し、上流切断時にリセットします。Tuner Gainは「自動（Tuner AGC）」または手動のdB値を表示します。ゲインインデックスのコマンドではdBへの変換表を取得できないため「手動 #番号」と表示します。

配信中は🟢、接続中・再接続中は🟡、停止・エラーは🔴で表示します。接続台数と全クライアントへの合計配信速度も更新します。詳細な状態やエラー理由はログで確認できます。

個別の操作権限や権限移譲はありません。選択したモードが全接続アプリに適用されます。

## 接続が切れた場合

- **rtl_tcpに接続できない**: 接続先、ポート、rtl_tcpの起動状態、ファイアウォールを確認してください。通常のrtl_tcpは1接続のため、他のアプリが直接接続していないかも確認します。
- **rtl_tcpを起動できない・すぐ終了する**: 実行ファイルのパス、USBドングル、WinUSBドライバー、DLLを確認します。同じドングルを使用する他のアプリがないかも確認してください。ログにはrtl_tcpの標準出力とエラー出力を表示します。
- **再接続中**: 上流復旧まで自動で再試行します。復旧後は受信アプリを再接続してください。集中管理の設定は自動で再適用します。
- **配信ポートを使用できない**: 通常画面の「配信ポート」を別の番号へ変更してください。
- **特定のアプリが切断される**: 受信が追いつかない場合、他のアプリの配信を維持するためその接続を切断します。ネットワーク状態やサンプルレートを確認してください。
- **接続数が上限**: 初版の同時接続上限は16アプリです。不要な接続を切断してください。

画面下部のログで原因を確認できます。長い状態メッセージや説明、設定ファイルのパスはツールチップで全文を確認できます。

## 停止と設定保存

「配信停止」で上流と全受信アプリの接続を閉じます。ウィンドウを閉じた場合も配信を停止します。初版はトレイへ常駐しません。

設定（受信元の選択、実行ファイルのパス、接続先など）は `%LOCALAPPDATA%\RTL-TCP-Cast\settings.ini` にUTF-8のINI形式で保存します。

設定は変更後に自動保存します（入力の連続書き込みを避けるため約300ミリ秒後）。入力途中の空欄や不正なポート番号は保存せず、最後の有効な設定を維持します。配信開始時とアプリ終了時にも保存し、次回起動時に復元します。自動で配信開始はしません。

旧バージョンのsettings.jsonがある場合、INIがまだ存在しなければ初回起動時に内容を移行します。元のJSONは残し、その後はINIを優先して読み込みます。手動編集はアプリを閉じてから行ってください。

## Windows起動時の自動起動

「設定 → アプリ全体の設定」の「Windows起動時に自動起動」を有効にすると、現在のユーザーがWindowsへサインインしたときにRTL-TCP-CASTを起動します。無効にすると登録を解除します。配信は手動で開始します。アプリを別のフォルダーへ移動した場合は、この設定を一度無効にしてから再度有効にしてください。

## RTL-SDRのシリアル番号を変更する

「設定 → シリアル番号変更…」を開くと、全タブの配信を停止し、アプリが起動したrtl_tcpも終了します。プルダウンでデバイスを選択し、新しいIDを入力して「保存」を押してください。外部で起動したrtl_tcpや他の受信ソフトがそのデバイスを使用している場合は、先に終了してください。

IDには半角英数字・ハイフン・アンダースコアを使用できます。文字数の上限は選択デバイスのEEPROMを読んで算出し、画面に表示します。空欄・上限超過・接続中の他デバイスと重複するIDは保存できません。

書き込み前のEEPROMは `%LOCALAPPDATA%\RTL-TCP-Cast\eeprom-backups` にバックアップし、書き込み後は読み直して検証します。USBを抜き差ししてから各タブのデバイス一覧を更新してください。配信は自動再開しません。一意の文字列シリアルで指定していたタブは、新しいIDへ更新します。数値のIDはrtl_tcpではデバイス番号として扱われるため、文字を含むIDを推奨します。
